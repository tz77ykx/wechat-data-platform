# 2026-11-13 公开发布前验证修复

## 发文预测页面模板缺失

- 问题：`/predict` 路由引用 `predict.html`，但模板文件不存在，页面返回 500。
- 影响范围：发文预测页面及从预测页进入推送日历的完整工作流不可用。
- 出错原因：功能路由、数据库字段和测试已存在，但页面模板没有随代码保留下来；此前只依据文档判断功能完成，没有执行页面验证。
- 修复方法：补齐七维评分页面，实现实时规则预估、AI 预打分提示词、预测保存、真实结果回填和推送日历参数联动。
- 验证：65 项 Python 测试通过；空数据库页面冒烟测试通过；Playwright 真实浏览器完成评分、保存、回填和日历跳转。
- 后续避免：页面功能交付必须实际请求页面，并覆盖主要用户操作，不能只检查路由或文档。

## 同步脚本状态判断使用转义引号

- 问题：`sync_to_mac_mini.sh` 在 `[` 判断和 `echo` 中使用了不必要的反斜杠转义引号。
- 影响范围：远程同步后的 HTTP 状态判断可能不能按预期执行，成功提示也会带上多余字符。
- 出错原因：脚本中混用了适合嵌入字符串的转义写法与直接 shell 语法。
- 修复方法：改用普通 shell 引号，并将远端地址和平台 URL 改为环境变量配置。
- 验证：`bash -n setup_mac.sh sync_to_mac_mini.sh` 通过。
- 后续避免：shell 修改后至少执行 `bash -n`，涉及状态判断时应使用本地 mock 服务验证成功和失败分支。

## 日期测试随当前日期失效

- 问题：两项主库查询测试使用 2026 年 3 月固定日期，而被测查询只读取最近 30 或 60 天。
- 影响范围：随着时间推移，正确代码也会出现测试失败，干扰发布判断。
- 出错原因：测试数据与基于 `date('now')` 的业务查询之间没有同步时间基准。
- 修复方法：测试数据改为根据当前日期生成，原始业务代码不变。
- 验证：完整 Python 测试套件 65 项通过。
- 后续避免：测试相对时间查询时使用动态日期或冻结时间，不写会自然过期的固定日期。

## 日历预填断言忽略 JSON Unicode 转义

- 问题：测试直接查找 JSON 中的中文字符串，但 Jinja `tojson` 默认输出 Unicode 转义。
- 影响范围：日历预填功能实际正常，测试却误报失败。
- 出错原因：测试把 JSON 当作普通 HTML 文本匹配，没有先解析数据。
- 修复方法：从页面提取预填 JSON，解析后逐项断言字段值。
- 验证：相关测试及完整 Python 测试套件通过，浏览器中也核对了 `window.pushCalendarPrefill` 的实际值。
- 后续避免：验证结构化数据时先解析，再比较字段，避免依赖编码和排版格式。
